# Flashcards

A browser-based app for creating, organizing, and studying flashcard decks.

## Live demo

https://flashcards-snowy-eta.vercel.app/

## Features

- Create, rename, and delete decks.
- Create, edit, and delete cards.
- Study cards with flip, previous/next navigation, and shuffle controls.
- Search card questions and answers.
- Persist decks and the active deck in browser localStorage.
- Responsive layouts for desktop and smaller screens.
- Accessible controls, keyboard navigation, focus handling, and screen-reader announcements.

## Keyboard shortcuts

- `Space`: flip the current card.
- `Left Arrow`: show the previous card.
- `Right Arrow`: show the next card.
- `Escape` in the search field: clear the search.

## Tech stack and running locally

Built with Angular and Angular Material. The Angular CLI build step compiles the TypeScript and Angular templates, then bundles the app's static assets for deployment. The live demo is already deployed and needs no setup.

To run the app locally:

```bash
npm install
npm start
```

Then open http://localhost:4200/.

## Reflection

- **Where AI saved time:** Copilot (Free plan, Agent mode) generated most of the feature code from one detailed prompt per phase: deck and card dialogs with validation, the CSS 3D flip animation, study navigation with keyboard shortcuts, and `localStorage` persistence. Because the free plan allows only 50 chat requests a month, I did the setup myself with the Angular CLI (`ng new`, `ng add @angular/material`, `ng generate` for every component and service) and used Copilot only for feature logic. Generating the feature logic took about 45 minutes instead of the 4 hours I'd estimate by hand.

- **AI bug I found and fixed:** Long deck names broke the sidebar and pushed the rename and delete buttons out of view. The cause was that Angular Material wraps button content in its own `.mdc-button__label` span, which wouldn't shrink, so the `text-overflow: ellipsis` on the title never took effect. I made that label a shrinkable flex row (`min-width: 0`), let the title truncate, kept the card count and icon buttons at fixed size, and added a tooltip with the full name. I used Claude to diagnose the Material label issue. The same review caught a second bug: the count showed "1 cards". I fixed it with a singular/plural check.

- **Code I refactored for clarity:** The deck row styles mixed two jobs in one rule. `.deck-title` and `.deck-count` shared the same truncation styles, and `margin-left: auto` was meant to push the count right but did nothing. I split them so each rule has one job:

  ```scss
  .deck-title {
    flex: 1 1 auto;
    min-width: 0;
    overflow: hidden;
    text-overflow: ellipsis;
    white-space: nowrap;
  }

  .deck-count {
    flex-shrink: 0;
    white-space: nowrap;
  }
  ```

  Now it's clear which element truncates and which never does.

- **Accessibility improvement:** Truncated deck names stay readable in full through a `matTooltip` that appears on both hover and keyboard focus. The rename and delete icon buttons have aria-labels that include the deck name (for example "Delete Spanish verbs"), so screen reader users know which deck each button acts on.

- **Prompt changes that improved AI output:** I put the project rules in `AGENTS.md` (generated by the Angular CLI's VS Code option), so every Copilot request followed the same conventions: signals, MatDialog for modals, aria-labels on icon buttons, no hard-coded colors. After Copilot generated inline `<svg>` icons, I added "always use `<mat-icon>`, never inline `<svg>`" to the rules and the QA prompt, then confirmed by searching `src` for `<svg>`. I also started a new chat for each phase, which kept responses focused and didn't use extra requests.
